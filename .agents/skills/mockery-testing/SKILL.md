# Mockery Testing: Strict Mock Generation Standard

## Overview

In this repository, **all unit test mocks for Go interfaces MUST be generated using Mockery**.

Handwritten mock structs, ad-hoc inline stubs (e.g. `type stub... struct`), or custom fake implementations of interfaces in `*_test.go` are **strictly forbidden**. This standard ensures consistent mock behavior, eliminates maintenance overhead of manual stubs, and leverages `testify/mock` verification across all modules.

## When To Use

| Use this skill when... | Use another skill or tool when... |
| ---------------------- | --------------------------------- |
| Writing a unit test that depends on an interface (repo, usecase, validator, logger, etc.) | Integration testing with real DB/Redis/Docker -> `tests/integration/` |
| Adding or updating an interface method that breaks existing generated mocks | Testing pure business logic without external dependencies |
| Refactoring legacy handwritten stubs (`stub*`) to Mockery mocks | End-to-end user flows -> `tests/e2e/` |

## Read Order

1. `AGENTS.md` (Hard architectural invariants & mocking standard)
2. `.mockery.yml` (Repository mock generation configuration)
3. Target interface definitions (e.g. `internal/modules/<module>/repository/`, `internal/modules/<module>/usecase/`)
4. Target unit test file (`*_test.go`)

## Hard Rules

1. **NO Handwritten Stubs**: NEVER declare `type stub... struct` or inline mock structs in `*_test.go` or test packages.
2. **Mockery Registration**: Every interface required for unit testing MUST be configured in `.mockery.yml`.
3. **Canonical Generation Command**: Always use `make mocks` to generate or regenerate mocks.
4. **Target Directory Convention**:
   - Module-specific mocks: `internal/modules/<module>/test/mocks/mock_<interface_name>.go` (package `mocks`)
   - Shared infrastructure / cross-module mocks: `internal/mocking/mock_<name>.go` or `pkg/<package>/mocks/`
5. **Assertion Standard**: Use `testify/mock` expectations (`mockObj.On("Method", ...).Return(...)`) and always assert expectations with `mockObj.AssertExpectations(t)` or `assert.True(t, mockObj.AssertExpectations(t))`.

## Step-by-Step Workflow

### Phase 1 — Identify Interfaces

Identify all interface dependencies required by the component under test (e.g. `UserRepository`, `AuditLogger`, `SettingsResolver`, `RelationValidator`).

### Phase 2 — Configure `.mockery.yml`

If the package containing the interface is not already listed in `.mockery.yml`, add it under `packages:`.

Example configuration:
```yaml
packages:
  github.com/Roisfaozi/queue-base/internal/modules/queue/repository:
    config:
      dir: internal/modules/queue/test/mocks
      filename: mock_queue_repository.go
```

If multiple interfaces exist in the package or custom naming is needed, specify interface configs accordingly following `.mockery.yml` conventions.

### Phase 3 — Generate Mocks

Run the canonical make target:
```bash
make mocks
```

Verify that the mock file is created/updated with the header:
```go
// Code generated by mockery; DO NOT EDIT.
```

### Phase 4 — Write Unit Tests with Mockery

Import the generated mock package and instantiate the mock in your test:

```go
import (
    "testing"
    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/mock"
    "github.com/Roisfaozi/queue-base/internal/modules/example/test/mocks"
)

func TestExampleUseCase_Execute(t *testing.T) {
    mockRepo := mocks.NewMockExampleRepository(t)

    // Setup expectations
    mockRepo.On("FindByID", mock.Anything, "test-id").Return(&entity.Example{ID: "test-id"}, nil).Once()

    // Execute usecase
    uc := usecase.NewExampleUseCase(mockRepo)
    result, err := uc.Execute(context.Background(), "test-id")

    // Assert
    assert.NoError(t, err)
    assert.NotNil(t, result)
    mockRepo.AssertExpectations(t)
}
```

## Anti-Patterns & Common Mistakes

- **Writing inline stubs**:
  ```go
  // WRONG: Strictly prohibited
  type stubQueueRepo struct {
      getQueueFunc func(ctx context.Context, id string) (*entity.Queue, error)
  }
  ```
  Instead, use `mocks.NewMockQueueRepository(t)` generated by `make mocks`.
- **Modifying generated mocks manually**: Never edit files containing `// Code generated by mockery; DO NOT EDIT.`. Update the interface and re-run `make mocks`.
- **Forgetting `.mockery.yml` entry**: Mockery will skip packages not declared in `.mockery.yml`. Always add new interface packages there.
- **Using broad argument matchers everywhere**: Match exact arguments where relevant instead of abusing `mock.Anything`, especially for tenant IDs and critical IDs.

## Verification

After generating mocks and writing tests:
1. Verify mock generation: `make mocks`
2. Run target unit tests: `make test-custom RUN='<TestName>' PKG=./internal/modules/<module>/...`
3. Verify all unit tests pass: `make test`
